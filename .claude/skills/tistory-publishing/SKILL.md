# 티스토리 퍼블리싱

## 이 스킬의 전제

이 프로젝트는 티스토리 계정에 직접 접근할 수단이 없다(로그인 세션도, 검증된 Open API 자격증명도 없음). 그래서 산출물은 항상 **"사용자가 티스토리 에디터에 붙여넣기만 하면 되는 상태"**까지이고, 실제 [발행] 버튼은 사용자 몫이다. 자동 게시를 시도하거나 게시된 것처럼 보고하지 않는다.

## Tistory Open API에 대한 주의

Tistory Open API(신규 글 작성을 프로그램으로 수행하는 API)는 한때 카카오가 신규 앱 등록을 막았던 이력이 있고, 정책은 시점에 따라 바뀔 수 있다. **API로 자동 발행이 가능하다고 단정하지 않는다.** 사용자가 이미 발급받은 앱/액세스 토큰을 갖고 있다고 명시적으로 알려주기 전까지는 항상 "복사해서 붙여넣는" 수동 발행 경로를 기본값으로 삼는다.

## 최종 결과물: `posts/{YYYY-MM-DD}-{slug}/`

```
posts/2026-09-01-free-korean-fonts/
├── final.html          ← 티스토리 에디터 "HTML 모드"에 그대로 붙여넣을 내용
├── meta.md              ← 제목/카테고리/태그/메타디스크립션/썸네일/제외 항목
└── attachments/
    └── README.md        ← 실제로 준비해서 첨부해야 할 파일 목록과 안내
```

## HTML 변환 규칙

티스토리 에디터는 기본(WYSIWYG)/마크다운/HTML 세 모드를 지원한다. 여러 writer의 마크다운 draft를 합칠 때는 마크다운을 그대로 넘기지 않고 **HTML로 변환**하는 것을 기본으로 한다 — HTML 모드가 서식 손실 없이 가장 예측 가능하게 이식된다.

- 코드블록: `<pre><code class="language-{언어}">...</code></pre>` 형태로 감싼다. 티스토리 코드블록 삽입 기능(자체 하이라이팅)을 쓸 수 있으면 그 형식을 우선하되, 최신 UI를 확신할 수 없으면 표준 `<pre><code>`로 안전하게 만들고 "티스토리 코드블록 기능으로 다시 감싸면 하이라이팅이 더 예쁘게 나온다"고 `meta.md`에 안내만 남긴다.
- 이미지: `<img>` 태그에 `alt` 텍스트를 반드시 채운다(접근성 + 이미지 검색 SEO). 실제 이미지 파일은 없으므로 `src`는 `{{IMAGE: 파일명}}` 같은 플레이스홀더로 남기고, writer가 draft에 남긴 "필요 이미지 목록"을 `attachments/README.md`에 그대로 옮겨 사용자가 무엇을 넣어야 하는지 알게 한다.
- 제목 구조: `<h2>`부터 시작한다(티스토리 스킨이 대개 글 제목을 `<h1>`로 별도 렌더링하므로 본문에서 `<h1>`을 또 쓰면 SEO상 제목이 중복된다).
- 표: `<table>`로 그대로 옮긴다(라이선스 표, 비교표 등).

## SEO 체크리스트 (발행 전 필수)

- [ ] 제목에 핵심 키워드가 자연스럽게 포함되어 있는가 (억지 삽입 아님)
- [ ] 메타디스크립션 1~2문장 — 검색 결과 스니펫에 노출될 문구를 `meta.md`에 별도 기재
- [ ] 모든 이미지에 `alt` 텍스트가 있는가
- [ ] 외부 링크(출처, 참고자료)가 깨지지 않았는가 — 가능하면 실제로 확인
- [ ] 제목 태그(`<h2>`/`<h3>`) 위계가 건너뛰지 않고 순차적인가
- [ ] 첫 문단에서 이 글이 무엇을 다루는지 바로 드러나는가 (검색 유입 독자는 스크롤 없이 판단한다)

## 품질 검수 체크리스트 (SEO와 별개)

- [ ] writer가 남긴 `<!-- 미검증 -->` / `<!-- 라이선스 미확인 -->` / `<!-- 검증 실패 -->` 주석이 모두 처리됐는가(포함 제외하고 `meta.md`에 사유 기록)
- [ ] 여러 writer 초안을 합쳤다면 문체가 통일됐는가
- [ ] 오탈자/띄어쓰기 — 특히 코드/프롬프트 원문이 아닌 설명 텍스트
- [ ] 코드블록에 언어 태그가 빠짐없이 있는가

## 카테고리/태그

- 카테고리는 `blog-editorial-planning`이 정의한 3축(디자인/코드/AI) 체계를 따른다. brief에서 제안된 카테고리를 그대로 쓰되, 이미 발행된 글의 카테고리와 일관성이 있는지 `posts/` 폴더를 훑어 확인한다.
- 태그는 5~8개, 너무 일반적인 단어(예: "블로그")보다 구체적 키워드 위주로 `meta.md`에 기재한다.

## meta.md 템플릿

```markdown
# 제목: {최종 제목}

- 카테고리: {디자인|코드|AI}
- 태그: {태그1, 태그2, ...}
- 메타디스크립션: {1~2문장}
- 썸네일: {어떤 이미지를 썸네일로 쓸지 지정 — attachments 목록 중 하나}

## 제외된 항목
- {항목명}: {제외 사유 — 예: 라이선스 미확인, 코드 검증 실패}

## 발행 안내
1. 티스토리 글쓰기 → HTML 모드 전환 → final.html 내용 붙여넣기
2. attachments/README.md 안내대로 실제 파일 준비해 첨부
3. 위 카테고리/태그/메타디스크립션 설정 후 발행
```
