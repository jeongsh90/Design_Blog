# 블로그 에디토리얼 기획

## 왜 기획 단계가 따로 필요한가

3개 축(디자인/코드/AI)을 한 사람이 아니라 여러 writer 에이전트가 나눠 쓰기 때문에, 기획서가 부실하면 writer들이 각자 다른 방향으로 글을 쓰거나 같은 내용을 중복해서 쓴다. 기획서는 "무엇을 쓸지"뿐 아니라 "누가 어디까지 쓸지" 경계를 그어야 한다.

## 카테고리 체계

기본 3축을 그대로 티스토리 카테고리로 매핑하는 것을 기본값으로 삼는다:

- **디자인** — 로고/폰트/디자인자료 아카이브, 디자인 트렌드, 툴 리뷰
- **코드** — 프론트엔드 개발, 퍼블리싱(HTML/CSS), 튜토리얼
- **AI** — 프롬프트 모음, Claude/Claude Code 스킬 자료, AI 도구

세부 카테고리(하위 폴더)가 필요해지면 실제 발행된 글 수가 각 축에서 10편을 넘어갈 때 세분화를 검토한다 — 글이 적은데 카테고리부터 잘게 쪼개면 각 카테고리가 텅 비어 보인다.

## 포스트 브리프 작성 규칙

브리프 하나가 곧 writer에게 넘어가는 작업 지시서다. 다음이 빠지면 writer가 임의로 채워 넣게 되어 톤·범위가 어긋난다:

1. **축 판정** — 단일 축인지, 복합(예: "AI로 만든 로고, 그 프론트엔드 구현까지")인지. 복합이면 각 writer의 담당 범위를 문장으로 명확히 나눈다: "design-content-writer는 로고 소스 소개까지, code-content-writer는 그 로고를 SVG로 반응형 구현하는 코드까지."
2. **타깃 독자 1줄** — "프론트엔드 입문자"와 "실무 5년차"는 같은 주제라도 완전히 다른 글이 나온다.
3. **제목 후보 2~3개 + 키워드** — 사람들이 검색할 법한 표현을 후보에 반영한다. 클릭베이트성 과장 제목은 피한다 — 퍼블릭 블로그의 신뢰는 제목과 내용의 일치에서 온다.
4. **큐레이션 글의 선정 기준** — "무료 폰트 모음"이라면 "상업적 이용 가능 + 한글 지원 + 최근 2년 내 업데이트"처럼 구체적 기준을 못박는다. 기준이 없으면 writer가 임의로 아무거나 채운다.
5. **튜토리얼의 전제 지식 수준** — "HTML 기초는 안다고 가정" 등, 안 그러면 너무 쉽거나 너무 어렵게 쓰인다.

## 에디토리얼 캘린더 (전체 전략 요청 시)

블로그 전체 전략을 짤 때는 다음을 포함한 `_workspace/00_strategist_editorial-plan.md`를 만든다:
- 3축 간 발행 비중 목표 (예: 균등, 또는 사용자가 더 집중하고 싶은 축 우선)
- 최근 발행 이력 요약 (`posts/` 폴더를 스캔해 어떤 주제가 이미 다뤄졌는지 — 중복 방지)
- 다음 3~5편의 제목 후보와 예상 축

## 검색 의도 확인

WebSearch/WebFetch가 가능하면 후보 키워드로 실제 검색해 이미 비슷한 글이 많은지, 어떤 각도가 덜 다뤄졌는지 확인한다. 확인이 어려우면 브리프에 "경쟁 콘텐츠 확인 안 됨"이라고 명시하고 넘어간다 — 확인했다고 거짓으로 적지 않는다.
