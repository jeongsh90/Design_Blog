# AI 프롬프트·스킬 자료 아카이브

## 왜 검증이 필요한가

AI 관련 콘텐츠는 "이 프롬프트 쓰면 대박"류의 검증되지 않은 과장이 유독 많은 영역이다. 이 블로그는 실제로 써보고 확인된 것만 다룬다는 점을 차별점으로 삼는다 — 확인 없이 옮겨 적기만 하면 흔한 AI 밈 계정과 다를 게 없다.

## 프롬프트 문서화 형식

프롬프트 하나를 소개할 때 아래를 모두 포함한다. 하나라도 빠지면 독자가 재현할 수 없는 자료가 된다:

```markdown
### {프롬프트 이름/용도}

**어떤 상황에 쓰는가:** ...
**확인한 모델/도구:** {예: Claude Sonnet 5, Claude Code, ChatGPT 등 — 정확한 이름과 가능하면 버전}

​```text
{프롬프트 원문 — 요약/의역 금지, 그대로}
​```

**실제 결과 요약:** (직접 확인했다면) 어떤 결과가 나왔는지 1~2문장
**주의사항/한계:** 이 프롬프트가 안 통하는 경우, 모델 바뀌면 결과가 달라질 수 있는지
```

## 검증 규칙

1. **가능하면 실제로 실행해본다.** 결과 스크린샷/요약을 남길 수 있으면 남긴다.
2. **실행이 어려운 환경(예: 유료 API 필요)이면 그 사실을 밝히고, 대신 공식 문서나 신뢰할 수 있는 1차 출처를 인용한다** — 출처 없는 2차 요약을 그대로 옮기지 않는다.
3. **모델/도구명을 흐리지 않는다.** "AI"라고만 쓰면 독자가 재현할 수 없다. 어떤 모델·어떤 도구인지 명시한다.
4. **오래된 정보를 최신인 것처럼 쓰지 않는다.** AI 도구/API는 빠르게 바뀐다 — 확인 시점을 명시하고, 불확실한 최신 사양(예: 특정 플랫폼의 API 등록 정책 변경 여부)은 "최신 상태는 직접 확인 필요"라고 명시한다.

## Claude Code 스킬/커맨드 자료를 다룰 때

- 소개하는 스킬/커맨드의 실제 파일 구조(frontmatter, 디렉토리 배치)를 코드로 검토해 최신 스펙과 맞는지 확인한다. 스펙이 바뀌었는데 옛 예시를 그대로 소개하면 독자가 그대로 따라 했을 때 동작하지 않는다.
- claude-api / claude-code-guide 같은 관련 참고 자료가 이 환경에 있으면 대조해 정확성을 높인다.

## 큐레이션(모음) 글 구성

여러 프롬프트/스킬을 모아 소개할 때는 용도별로 묶어 목차를 만든다(예: "글쓰기용", "코드 리뷰용", "리서치용"). 단순 나열보다 "언제 이걸 쓰면 좋은지" 기준의 분류가 실용성을 높인다.

## draft 말미 필수 섹션

```markdown
## 검증 기록
- 확인 모델/도구: {목록}
- 확인 시점: {날짜}
- 직접 검증한 항목: {목록}
- 미검증 항목: {목록 + 이유, 없으면 "없음"}
```
