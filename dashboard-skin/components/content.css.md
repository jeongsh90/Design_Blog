## 15. 독립 스크롤 컨테이너 [SPEC §2-1]

── 독립 스크롤 컨테이너 [SPEC §2-1] ──
     ★ height:100%는 쓰지 않는다(요청 문언과 다른 유일한 지점).
       부모(content-layout)의 높이가 확정돼 있지 않아 CSS 규칙상 auto로
       계산된다 — 선언해도 아무 일도 일어나지 않고, 유효하게 만들려면 셸

       max-height를 뷰포트 단위(svh)로 주면 부모 높이 확정이 필요 없어
       셸을 한 줄도 안 건드리고 같은 결과("본문이 뷰포트 높이를 채우고 그
       안에서 스크롤된다")를 얻는다. 우측 위젯 패널이 이미 검증한 패턴이다.

## 22. ★ [SPEC §2-3] position:sticky는 **추가하지 않았다.

★ [SPEC §2-3] position:sticky는 **추가하지 않았다.**
   판정 근거(2026-09-04 Playwright 실측): content-inner와 widgets 둘 다
   max-height ≤ 100svh − 56px이고 부모 content-layout은 align-items:flex-start
   이므로 content-layout ≤ 100svh − 56 → sidebar-inset ≤ 56 + (100svh − 56)
   = 100svh가 되어 **문서 레벨 스크롤이 구조적으로 발생하지 않는다.**
   실측: document.scrollingElement.scrollHeight === window.innerHeight(Δ0px).
   스펙 지시("거짓이면 추가하지 않는다")대로 불필요한 스택 컨텍스트/포지셔닝을
   만들지 않는다. 티스토리가 관리 메뉴바를 주입해 문서가 실제로 스크롤되기
   시작하면 그때 `position:sticky; top: var(--header-height)` 한 줄을 추가하면
   된다(위젯 패널과 동일 패턴).

## 24. ★ 퍼센트(min-height:100%)를 쓰면 안 된다: content-inner는 height가 아니라

★ 퍼센트(min-height:100%)를 쓰면 안 된다: content-inner는 height가 아니라
     max-height만 가진 **높이 불확정** 부모라, 자식의 min-height:100%는 CSS
     규칙상 0으로 계산되어 조용히 무효화된다. 뷰포트 기준으로 직접 계산한다 —
     (100svh − 56px) − content-inner 상하 패딩 24×2. 이 한 줄이 있어야
     글이 0개일 때도 격자가 캔버스를 가득 채운다.

## 30. 4. 리스트영역 — 글 목록  [SPEC §6]

════════════════════════════════════════════════════════════════
   4. 리스트영역 — 글 목록  [SPEC §6]
   ────────────────────────────────────────────────────────────────
   ★ card.css(Card 프리미티브)를 재사용하지 않는 이유 [SPEC §6-1]
     요구사항 문서엔 "card.css를 글 목록 카드에 그대로 재사용 가능"이라고
     적혀 있었지만, 이번 요청("리스트사이 여백없음 / 그리드영역에 맞게 배치")이
     그 전제를 무너뜨렸다. Card 원본 8개 선언 중 **7개를 덮어써야** 한다:
       flex-column → grid 6칸 / gap 16px → 행 6px·열 0 / padding-block 16px → 0
       (패딩이 높이에 더해져 격자 정합이 깨진다) / radius-xl 14px → 0
       (★ 라운드 코너는 맞붙여 타일링할 수 없다 — 요청과 원리적으로 상충)
       / bg-card → 투명(격자가 비쳐야 함) / 링 섀도 → inset 아래 1줄만.
     그건 재사용이 아니라 "프리미티브를 무력화한 뒤 새로 쓰는 것"이다.
     → card.css 원본은 **한 글자도 고치지 않는다**(다른 구역이 그대로 쓸 수
       있게 둔다). Badge/Button은 그대로 재사용한다.

   ★★ 이 구역에서 border-bottom은 금지한다 [SPEC §4-4]
     border-bottom:1px는 요소 높이를 1px 늘려(border-box가 아닌 한) 그 아래
     모든 경계를 1px씩 누적 이동시킨다 — 글 100개면 100px이 어긋난다.
     inset box-shadow는 레이아웃 높이에 전혀 영향을 주지 않으면서 같은 1px
     선을 그린다. (실측: 카드 10장 누적 오차 0px — 검증 문서 참고)
   ════════════════════════════════════════════════════════════════

## 158. [CODEBLOCK SPEC §5] 본문 코드블록 — shadcn 문서사이트(apps/v4) 정본 이식

파일 맨 끝의 코드블록 절과 520행대 `pre` 블록 교체분에 대한 설명이다.
소스에는 주석을 넣지 않는다(스펙 §10).

**정본 출처.** 레지스트리에 `code-block` 컴포넌트는 없다. 정본은 shadcn 문서
사이트 v4의 `apps/v4/app/globals.css` `@layer components`와
`lib/highlight-code.ts`(Shiki `codeToHtml` + rehype-pretty-code transformers)다.
그래서 이 스킨도 rehype-pretty-code가 **서버에서 만들었을 속성 이름 그대로**
(`data-rehype-pretty-code-figure` / `-title`, `data-line-numbers`, `data-line`,
`data-highlighted-line`) 쓰고, 정본 CSS를 한 글자도 바꾸지 않고 재사용한다.
만드는 주체만 서버 → `content.js`로 바뀌었다.

**로컬 변수 3개를 `[data-slot="content"]`에 둔 이유.** `--code-border`는
figure가 없는 폴백 경로(`pre` 단독, no-JS)에서도 필요하고, `--code-header` ·
`--code-bar`는 figure 안에서만 쓰인다. 셋 다 코드블록이 존재할 수 있는 가장
가까운 공통 조상 하나(`[data-slot="content"]`)에 모아 뒀다 — `content-inner`의
`--content-*` 관례와 같은 방식이다. `--code-border`만 `.dark`에서 다시 선언한다:
정본은 라이트·다크 모두 `--border` 30% 혼합이지만 이 스킨의 다크 `--border`는
이미 알파값(`#ffffff1a`)이라 30%를 다시 곱하면 3%로 사라진다.

**전역 토큰(`--code*` / `--radius-2xl`)은 `src/input.css`에 있다** — `input.css.md`
20번 참고.

**기존 프로즈 규칙과의 충돌 처리(스펙 §5-3).**

| 기존 규칙 | 충돌 | 처리 |
|---|---|---|
| `figcaption`(630행): `margin-top:2` · `text-align:center` · `color:--color-muted-foreground` · `word-break:keep-all` | 코드 헤더가 가운데 정렬 + 흐린 색 | `… [data-rehype-pretty-code-figure] > [data-rehype-pretty-code-title]`(특정성 (0,2,1) > (0,1,1))에서 4개 속성 전부 재선언 |
| `:is(blockquote,pre,figure,…) { margin-top: 6 }`(438행) | figure 안 `pre`에도 24px | `> pre { margin-top: 0 }` |
| `pre code { display: block }`(543행) | **정본 `[data-line-numbers] { display: grid }`가 진다**((0,1,0) < (0,1,2)) — 줄번호 grid가 통째로 무효화된다 | 스펙 §5-3 표에 없던 충돌이라 실측으로 발견. 정본 블록은 그대로 두고, `… > pre > code[data-line-numbers] { display: grid }` 한 줄을 §5-2 쪽에 추가해 특정성으로 되돌린다(정본 선택자를 고쳐 쓰지 않기 위한 최소 추가) |

**정본에 없어 보강한 3줄(스펙 §1-5).** ① `[data-highlighted-line]{position:relative}`
— 없으면 `:after` 세로 바가 그 줄이 아니라 figure 전체 높이로 그려진다(실측 확인).
② `[data-rehype-pretty-code-title]`의 `border-bottom-width/style` — 정본 발췌의
`border-bottom: color-mix(...)`는 색만 있는 축약형이라 보더가 렌더되지 않는다
(이 스킨은 §5-2에서 이미 `1px solid` 축약으로 선언하므로 이 두 줄은 중복 안전망).
③ `[data-line]{min-height: calc(var(--leading-relaxed) * 1em)}` — 폴백 경로는 순수
텍스트 분할이라 빈 줄에 텍스트 노드가 없어 높이가 0으로 접히고 줄번호가 어긋난다.

**정본과 의도적으로 다른 것(오케스트레이터 채택값).** Q2=b 헤더만 `--code-header`
(foreground 4% 혼합)로 한 단계 어둡게 / Q3=b figure `1px solid`(정본은
`border-width:0` — 라이트에서 `#fafafa` on `#ffffff`가 안 보인다) / 복사 버튼은
figure 기준 absolute가 아니라 `figcaption` 안 flow 배치(`margin-left:auto`,
헤더 높이는 `min-height: calc(var(--spacing) * 10.5)`로 정본 42px 유지).

**Q1=B (2026-09-05).** 정본의 `[data-line] span { color: var(--shiki-light) }` /
`.dark … --shiki-dark`는 제거했다. 토큰 색은 스펙 §8-1의 `.hljs-*` 클래스 표로
라이트/다크를 `content.css`에 직접 둔다. github 테마 CSS 파일은 로드하지 않는다.
